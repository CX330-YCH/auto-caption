# Auto Caption ユーザーマニュアル

対応バージョン：v2.18.0

この文書は大規模モデルを使用して翻訳されていますので、内容に正確でない部分があるかもしれません。

## ソフトウェアの概要

Auto Caption は、クロスプラットフォームの字幕表示ソフトウェアで、システムの音声入力（録音）または出力（音声再生）のストリーミングデータをリアルタイムで取得し、音声からテキストに変換するモデルを利用して対応する音声の字幕を生成します。このソフトウェアが提供するデフォルトの字幕エンジン（アリババクラウド Gummy モデルを使用）は、9つの言語（中国語、英語、日本語、韓国語、ドイツ語、フランス語、ロシア語、スペイン語、イタリア語）の認識と翻訳をサポートしています。

現在のデフォルト字幕エンジンは Windows、macOS、Linux プラットフォームで完全な機能を有しています。macOSでシステムのオーディオ出力を取得するには追加設定が必要です。

以下のオペレーティングシステムバージョンで正常動作を確認しています。記載以外の OS での正常動作は保証できません。

| OS バージョン        | アーキテクチャ | オーディオ入力取得 | オーディオ出力取得 |
| ------------------- | ------------- | ------------------ | ------------------ |
| Windows 11 24H2     | x64           | ✅                  | ✅                  |
| macOS Sequoia 15.5  | arm64         | ✅ 追加設定が必要      | ✅                  |
| Ubuntu 24.04.2      | x64           | ✅                  | ✅                  |
| Kali Linux 2022.3   | x64           | ✅                  | ✅                  |
| Kylin Server V10 SP3 | x64 | ✅ | ✅ |

### ソフトウェアの欠点

Gummy 字幕エンジンを使用するには、アリババクラウドの API KEY を取得する必要があります。

macOS プラットフォームでオーディオ出力を取得するには追加の設定が必要です。

ソフトウェアは Electron で構築されているため、そのサイズは避けられないほど大きいです。

## Gummyエンジン使用前の準備

ソフトウェアが提供するデフォルトの字幕エンジン（Alibaba Cloud Gummy）を使用するには、Alibaba Cloud百煉プラットフォームからAPI KEYを取得する必要があります。その後、API KEYをソフトウェア設定に追加するか、環境変数に設定します（Windowsプラットフォームのみ環境変数からのAPI KEY読み取りをサポート）。

**Alibaba Cloudの国際版サービスではGummyモデルを提供していないため、現在中国以外のユーザーはデフォルトの字幕エンジンを使用できません。**

この部分についてAlibaba Cloudは詳細なチュートリアルを提供しており、以下を参照できます：

- [API KEY の取得（中国語）](https://help.aliyun.com/zh/model-studio/get-api-key)
- [環境変数を通じて API Key を設定（中国語）](https://help.aliyun.com/zh/model-studio/configure-api-key-through-environment-variables)

## GLM エンジン使用前の準備

まずAPI KEYを取得する必要があります。参考：[クイックスタート](https://docs.bigmodel.cn/en/guide/start/quick-start)。

## Fun-ASR Realtime を使用する前の準備

Alibaba Cloud Model Studio の同じ Workspace とリージョンから、API Key、Workspace ID、専用 WebSocket Endpoint を用意してください。Endpoint は北京またはシンガポールの公式 `wss://<WorkspaceId>.<region>.maas.aliyuncs.com/api-ws/v1/inference` 形式で、ホスト内の Workspace ID と設定値が一致する必要があります。オンライン利用には料金が発生する可能性があるため、[公式 WebSocket API 文書](https://help.aliyun.com/zh/model-studio/fun-asr-realtime-websocket-api)と現在の料金を確認してください。

画面ではモデル、意味句読点、最大文間無音（200–6000 ms）、ハートビートを設定できます。Fun-ASR の final 文は既存の外部翻訳設定を使用します。

字幕エンジンは起動時に OS ネイティブの CA 信頼ストアを初期化します。macOS では Security とキーチェーンの信頼、Windows では CryptoAPI、Linux ではシステムの OpenSSL 証明書パスを使用します。企業プロキシやプライベート CA は、先にシステム信頼ストアへ正しくインストールしてください。アプリは TLS 証明書検証を無効化せず、パッケージ版 Python に存在しない場合がある独立 CA ファイルにも依存しません。

「詳細設定」のホットワードは2段階です。レベル1では既存の語彙 ID と対象モデル、および1行1件のコンテキスト用語を指定します。コンテキストに重みはなく、合計400文字までで、語彙と併用できます。認識に使用するには「変更を適用」を押してください。レベル2は適用済み API Key の所有アカウント、Workspace、リージョン、モデルを使い、リモート語彙の一覧、作成、完全置換、削除を行います。リモート更新は即時反映され、「変更をキャンセル」では戻せません。削除時は対象情報を再表示して確認します。語彙モデルは認識モデルと完全に一致する必要があります。Alibaba Cloud の現行説明では、シンガポールのサブ Workspace はホットワード非対応です。

## macOS でのシステムオーディオ出力の取得方法

> [マルチ出力デバイスの設定](https://github.com/ExistentialAudio/BlackHole/wiki/Multi-Output-Device) チュートリアルに基づいて作成


字幕エンジンは macOS プラットフォームで直接システムオーディオ出力を取得できず、追加のドライバーインストールが必要です。現在の字幕エンジンでは [BlackHole](https://github.com/ExistentialAudio/BlackHole) を使用しています。まずターミナルを開き、以下のいずれかのコマンドを実行してください（最初のオプションを推奨します）：

```bash
brew install blackhole-2ch
brew install blackhole-16ch
brew install blackhole-64ch
```

![](../img/03.png)

インストール完了後、`オーディオMIDI設定`（`cmd + space`で検索可能）を開きます。デバイスリストにBlackHoleが表示されているか確認してください - 表示されていない場合はコンピュータを再起動してください。

![](../img/04.png)

BlackHoleのインストールが確認できたら、`オーディオ MIDI 設定`ページで左下のプラス(+)ボタンをクリックし、「マルチ出力デバイスを作成」を選択します。出力に BlackHole と希望するオーディオ出力先の両方を含めてください。最後に、このマルチ出力デバイスをデフォルトのオーディオ出力デバイスに設定します。

![](../img/05.png)

これで字幕エンジンがシステムオーディオ出力をキャプチャし、字幕を生成できるようになります。

## Linux でシステムオーディオ出力を取得する

まずターミナルで以下を実行してください:

```bash
pactl list short sources
```

以下のような出力が確認できれば追加設定は不要です:

```bash
220     alsa_output.pci-0000_02_02.0.3.analog-stereo.monitor    PipeWire        s16le 2ch 48000Hz       SUSPENDED
221     alsa_input.pci-0000_02_02.0.3.analog-stereo     PipeWire        s16le 2ch 48000Hz       SUSPENDED
```

それ以外の場合は、以下のコマンドで`pulseaudio`と`pavucontrol`をインストールしてください:

```bash
# Debian/Ubuntu系の場合
sudo apt install pulseaudio pavucontrol
# CentOS系の場合
sudo yum install pulseaudio pavucontrol
```

## ソフトウェアの使い方

### 設定の変更

字幕の設定は3つのカテゴリーに分かれます：一般的な設定、字幕エンジンの設定、字幕スタイルの設定。注意すべき点として、一般的な設定の変更は即座に適用されます。しかし、他の2つの設定については、変更後に該当する設定モジュール右上の「適用」オプションをクリックすることで初めて変更が有効になります。「変更を取り消す」を選択すると、現在の変更は保存されず、前回の状態に戻ります。

字幕コントロールウィンドウの最小サイズは 900×600 です。コンテンツ領域の幅が 1200px 未満になると、設定パネルは左側の「設定」レールに折りたたまれます。マウスを合わせるかキーボードでフォーカスすると一時的に開き、クリックすると開いた状態を固定できます。もう一度クリックする、設定領域の外側をクリックする、または Esc を押すと閉じます。未適用の字幕エンジンと字幕スタイルの下書きは、パネルの開閉やレスポンシブ境界をまたぐサイズ変更でも失われません。設定フォームの最大幅は 640px で、左側領域を広げてもラジオボタン、セレクト、入力欄、スライダーが際限なく引き伸ばされることはありません。フォームが 480px 以下の場合、通常の項目は統一された上下配置になります。言語・テーマ・色・字幕行数はまとまった単位として配置され、スイッチのラベルは左揃え、スイッチ本体は同じ列に保たれるため、途中で孤立した行に分断されません。字幕スタイルの原文・翻訳フォントでは、現在のシステムがアプリに列挙を許可したローカルフォントを検索できます。フォント名は一覧を初めて開いた時だけ読み取り、ローカルメモリ内だけで使用します。フォントファイルやフォント一覧をアップロードすることはありません。列挙が未対応または拒否された場合や、設定したフォントがインストールされていない場合は、手動入力に切り替えて単一のフォント名または完全な CSS フォントスタックを引き続き利用できます。列挙失敗で既存値が上書きされることはありません。フォント変更もスタイルの下書きであり、「適用」を押した後に字幕ウィンドウへ反映されます。字幕スタイルのプレビューは右ペイン下部に固定され、高さはコンテンツ領域の 35% までです。超過した内容はプレビュー領域内だけでスクロールし、字幕記録を覆いません。

現在のバージョンは `schemaVersion: 5` の階層化設定を使用します。完全な V2 設定は V3、V4、V5 の順に移行され、V3/V4 も残りの手順で V5 へ移行します。表示方式は「文単位表示」、文境界モードは「文ごとに改行」が既定のため、アップグレードしても従来の字幕動作は変わりません。バージョンなし設定は引き続き既定値になります。

字幕エンジン設定は、選択したエンジンの言語と専用項目を表示します。翻訳を無効にすると翻訳サービスの項目と起動引数は非表示・未送信になります。有効にした後、「翻訳エンジンを設定」で Provider、モデル、Base URL、API Key を展開できます。「詳細設定」には選択中のエンジンの資格情報またはローカルモデルパスと共通設定が表示されます。エンジンを切り替えても保存済み設定は削除されず、「変更を適用」で保存されます。

### 字幕の開始と停止

すべての設定を完了したら、インターフェースの「字幕エンジンを開始」ボタンをクリックして字幕を開始できます。独立した字幕表示ウィンドウが必要な場合は、インターフェースの「字幕ウィンドウを開く」ボタンをクリックして独立した字幕表示ウィンドウをアクティブ化します。字幕認識を一時停止する必要がある場合は、「字幕エンジンを停止」ボタンをクリックします。

### 字幕表示ウィンドウの調整

下の図は字幕表示ウィンドウです。同じ文のストリーミング字幕はその場で増分更新され、確定後の文が遅延した中間結果で上書きされることはありません。字幕スタイルでは「文単位表示」と「行単位スクロール」を選択できます。文単位表示は従来の最新字幕を表示する方式を保持し、両方の表示方式で文字を左右対称の安全余白内に表示します。行単位スクロールは現在の内容幅、フォント、文字サイズで常に正確に折り返します。幅不足による自動折り返しで完成した行だけを両端揃えにし、文境界で終わる行と現在の最終行は左揃えを保ちます。原文と翻訳文はそれぞれ「字幕行数」で指定した表示行数を保持して独立にスクロールするため、遅延した翻訳文が原文を押し出すことはありません。行単位スクロールでは「文ごとに改行」と「連続レイアウト」も選択できます。前者は各字幕を新しい行から表示し、後者は実際の幅で折り返すまで次の字幕を前の文末に続けます。1つの選択が原文と翻訳文に同時に適用されますが、両トラックは独立したままです。末尾に新しい行が現れると同じトラックの古い行を約 500ms で上へ移動し、過去の翻訳の追加、ウィンドウ幅、フォントの変更は新着字幕として扱わず再レイアウトします。OS の「視差効果を減らす」が有効な場合はアニメーションしません。右側のツールバーは自動的に隠れ、ポインターがウィンドウまたはツールバーに入るか、キーボードフォーカスを受けると再表示されます。ツールバーはオーバーレイであり、字幕のレイアウト幅を消費しません。3つのボタンは、字幕表示ウィンドウを閉じる、字幕制御ウィンドウを開く、マウス透過を有効化する機能です。ウィンドウの左右の端をドラッグして幅を調整できます。

![](../img/01.png)

### 字幕記録のエクスポート

「エクスポート」ボタンをクリックすると、字幕記録を JSON または SRT ファイル形式で出力できます。

### 完全 Debug ログの保存

「ログ記録」画面は従来どおり INFO、WARN、ERROR のみを表示し、DEBUG は表示しません。問題調査時は「完全な Debug ログを保存」をクリックすると、今回のソフトウェア起動以降の完全なセッションを `.jsonl` ファイルとして保存できます。表示中ログの「クリア」はセッションファイルを削除しません。構造化診断フィールドと例外スタックは保持されますが、API Key、Token、Password、Authorization は常にマスキングされます。エクスポート対象はボタンを押した時点までに生成された記録です。

## 字幕エンジン

字幕エンジンとは、システムのオーディオ入力（録音）または出力（再生音）のストリーミングデータをリアルタイムで取得し、音声テキスト変換モデルを呼び出して対応する字幕を生成するサブプログラムです。生成された字幕は JSON 形式の文字列に変換され、標準出力を通じてメインプログラムに渡されます。メインプログラムは字幕データを読み取り、処理した後、ウィンドウに表示します。

ソフトウェアには5つの内蔵字幕エンジンがあります。エンジンメニューの「カスタムエンジンを追加…」を選び、表示名を入力すると、新しい項目が作成・選択され、その後もメニューに残ります。各カスタム項目の右側には削除ボタンがあります。パスは実行ファイル、コマンドは起動引数です。

![](../img/02_ja.png)

カスタム字幕エンジンを使用する場合、前の字幕エンジンの設定はすべて無効になります。カスタム字幕エンジンの設定は完全にエンジンコマンドによって行われます。

開発者の方で、カスタム字幕エンジンを開発したい場合は、[字幕エンジン説明文書](../engine-manual/ja.md)をご覧ください。
